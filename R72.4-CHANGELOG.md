# TOR POS R72.4 – Backup File-Lock Hotfix

## Hata
R72.3 Windows testinde R55 FullBackup cleanup sırasında:

`IOException: ... TOR-POS-....db ... being used by another process`

oluştu.

## Kök neden
DatabaseBackupService geçici snapshot DB bağlantısını varsayılan SQLite
connection pooling ile açıyordu.

Windows'ta Dispose/Close sonrasında pooled native SQLite handle yaşamaya devam
edebilir. FullBackupService bu snapshot'ı staging klasörüne taşıdıktan sonra
staging klasörünü silmeye çalışınca dosya kilidi kalabiliyordu.

## Düzeltme
Geçici backup destination:
- `Pooling = false`
- `Cache = SqliteCacheMode.Private`
- explicit using scope
- path çağırana dönmeden bütün destination handles dispose edilir

Ana üretim veritabanının pooling davranışı değiştirilmedi.

## Cleanup dayanıklılığı
Windows Defender / indexer gibi çok kısa süreli file handle yarışları için:
- staging directory delete bounded retry
- temporary archive delete bounded retry
- failed restore cleanup bounded retry

Kalıcı lock sessizce yutulmaz; retry sonunda yine IOException olur.

## Safety testi
Toplam test sayısı artırılmadı; mevcut kontroller güçlendirildi.

R54 artık backup DB dosyalarının dönüşten sonra `FileShare.None` ile exclusive
açılabildiğini doğrular.

R55 artık FullBackup tamamlandıktan sonra yeni `tor-backup-*` staging klasörü
kalmadığını da doğrular.

Hedef:
`ALL 298 CHECKS PASSED`

LoginWindow/MainWindow/SettingsWindow DI/factory ile gerçek dependencies
üzerinden oluşturulur. Warning'i susturmak için dummy parameterless constructor
