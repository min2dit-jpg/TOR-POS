# TOR POS R75.1 – Application Namespace Hotfix

## Windows Buildfehler
R75 kompilierte Core, Application und Infrastructure erfolgreich.
TorPos.App brach jedoch ab mit:

`CS0118: 'Application' ist ein Namespace, wird aber wie ein Typ verwendet.`

Ursache:
R75 führte das Namespace `TorPos.Application` ein und importierte es in
`App.axaml.cs` mit:

`using TorPos.Application;`

Gleichzeitig erbt die Avalonia-App von:

`Application`

Dadurch konnte C# `Application` als Namespace statt als
`Avalonia.Application` auflösen.

Zusätzlich existiert in MainWindow:
`Application.Current`

Das hätte nach Behebung des ersten Fehlers denselben Namenskonflikt erzeugen
können.

## Fix
Keine Architektur wird zurückgenommen.

Statt eines breiten Namespace-Imports werden konkrete Type-Aliase verwendet:

App.axaml.cs:
`using CheckoutApplicationService = TorPos.Application.CheckoutApplicationService;`

MainWindow:
- `CheckoutApplicationService`
- `CheckoutApplicationDisposition`

werden explizit auf `TorPos.Application.*` aliasiert.

Damit bleibt:
- `App : Application` eindeutig Avalonia.Application
- `Application.Current` eindeutig Avalonia.Application.Current

## Unverändert
- TorPos.Application bleibt eigene Schicht.
- Application -> Core only.
- Schema bleibt V5.
- KIOSK/IMBISS-Trennung bleibt erhalten.
- R73 Payment Outcome bleibt erhalten.
- R74 SQLite/WAL Health bleibt erhalten.
- Safety-Ziel bleibt `ALL 348 CHECKS PASSED`.
- production_allowed=false.
